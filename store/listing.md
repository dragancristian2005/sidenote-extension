### Description

```
Sidenote puts an AI chat in your browser's side panel, so you can ask questions about whatever you are looking at without copy-pasting or switching tabs.

You bring your own API key. Your messages go straight from your browser to the AI provider you choose. There is no Sidenote server, no account, no analytics and no subscription.

WHAT YOU CAN ATTACH TO A MESSAGE (you choose, per message)
• Selection: the text you highlighted. It ticks itself when you select something.
• Page text: the readable text of the current tab.
• Other tabs: tick extra open tabs in the Tabs picker to ask across several pages at once.
• Screenshot: the visible part of the current tab, for models that can read images.
• PDF: the PDF open in the tab, sent in full, for models that support PDFs.
Nothing is attached unless you tick it.

BRING YOUR OWN KEY
Use the AI service you already have an API key for. Add the model IDs you want from your provider's docs and switch between them from the panel. Services with an OpenAI-compatible API also accept a custom base URL. The supported services are listed in the settings panel and the README.

MADE FOR LONG, REAL USE
• Saved chats with a History panel (text only; screenshots and PDFs are never stored).
• Old attachments are trimmed automatically from what is re-sent, which keeps long chats cheaper and more accurate.
• When a chat gets long, "Summarize & continue" starts a fresh chat from a summary and keeps the old one in History.
• Streaming answers, rendered Markdown, one-click copy for code blocks, automatic retry when a model is busy.
• Keyboard: Alt+G focuses the message box; Up/Down recalls your earlier messages.
• Light and dark themes follow your system.

PRIVACY BY DESIGN
• Nothing is sent until you press send.
• Your API keys and chats stay in your browser's local extension storage.
• No tracking, no ads, nothing sold or shared.
• Site access is requested per site, only when you attach content from it, and you can revoke it at any time. An optional "Allow all sites" switch is off by default.
• Open source: https://github.com/dragancristian2005/sidenote-extension
• Privacy policy: https://github.com/dragancristian2005/sidenote-extension/blob/main/PRIVACY.md

GOOD TO KNOW
• You need an API key from at least one provider. A chat subscription does not include API access. API usage is billed by the provider, and some offer a free tier.
• What happens to your data after it reaches the provider is governed by that provider's terms, including whether free-tier data may be used for training or review. Avoid attaching sensitive pages.
• Gemini users in the EEA, Switzerland or the UK: Google's API terms only allow Paid Services there, so use a key from a billing-enabled Google Cloud project, not a free-tier key.
• The title and URL of the current tab are sent with every message so the model knows what you are asking about.
• Browser-internal pages (brave://, chrome://) and the Web Store cannot be read.

Sidenote is an independent project and is not affiliated with, endorsed by or sponsored by any AI provider it can connect to. All product names are trademarks of their respective owners.
```

## Privacy tab

### Single purpose
> Sidenote lets you chat with an AI model of your choice, using your own API key, about the content of your current browser tab (selection, page text, screenshot, PDF) and other tabs you choose, in a browser side panel.

### Permission justifications

| Permission | Justification to paste |
|---|---|
| `activeTab` | Lets the extension access the tab the user is currently working in, when the user opens the panel from the toolbar, so it can read the selection or page text the user chooses to attach. |
| `scripting` | Used to read the user's text selection and the readable text of a tab, only when the user attaches that content to a message or has Selection auto-tick on. No code is injected for any other purpose. |
| `tabs` | Used to show the title of the current tab and to list the user's open tabs in the "Tabs" picker so the user can choose extra tabs to include. Titles and URLs are only sent to the AI provider the user selected, with their message. |
| `storage` | Stores the user's settings, API keys, model IDs and saved chats locally in the browser (`chrome.storage.local`). Nothing is synced or sent to the developer. |
| `sidePanel` | Shows the chat interface in the browser side panel. |
| Optional host permissions (`https://*/*`, `http://*/*`, `file:///*`) | Requested at runtime, per site, only when needed: (1) the API host of the AI provider the user selected, so the extension can send the user's message; (2) the site of a tab the user attaches content from, so the extension can read it, or download the PDF open in it. No site access is granted at install. An optional "Allow all sites" setting, off by default, lets users avoid repeated prompts. |

### Remote code
**No, I am not using remote code.** All JavaScript is packaged in the extension. The extension only sends data to the user's chosen AI API and receives text back.

### Data usage (what to tick in the form)
Declare conservatively, because page content and the tab URL are transmitted (to the user's own chosen AI provider, not to the developer):
- **Website content**: yes (text, screenshots and PDFs of pages the user attaches).
- **Authentication information**: yes (the user's API key is stored locally and sent to the provider as authentication).
- **Personal communications / user-provided messages**: if offered under your form's categories, tick it for the chat messages the user types.
- **Web history**: arguably yes for the active tab's title/URL sent with each message; tick it if you want to be safe.
- Leave the rest unticked (health, financial, location, personally identifiable information beyond the above, etc.).

Then tick all three certifications:
- I do not sell or transfer user data to third parties, outside of the approved use cases (the transfer to the AI provider the user selects is the extension's core function).
- I do not use or transfer user data for purposes unrelated to the item's single purpose.
- I do not use or transfer user data to determine creditworthiness or for lending purposes.

## Notes for the reviewer (Test instructions field)
```
Sidenote needs a user-supplied API key. To test without your own key:
1. Open the side panel (toolbar icon), click the gear, pick "Gemini", paste any key from https://aistudio.google.com/apikey (free tier), click Save, allow the API host when prompted.
2. Under "Add a model ID" enter a current model ID from https://ai.google.dev/gemini-api/docs/models and click Add.
3. Open any web page, select some text, type a question and press Enter. Allow site access when prompted.
All data goes directly from the browser to the chosen provider; the developer operates no server.
```
(If the reviewer cannot get a key, offer a temporary restricted key in the dashboard's "test instructions / credentials" field. Do not put a key in this repo.)
